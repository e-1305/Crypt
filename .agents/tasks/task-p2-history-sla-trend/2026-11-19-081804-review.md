# Run history, ageing and SLA trend for autopsy page and War Room (v1)

The change adds a per-limb JSONL history (`out/crypt-history.jsonl`: ts, limb, state, kev, epss, ownerTeam, deadline, plus a `source` label). `crypt autopsy` and `crypt gazette` append to it, and the Action uploads it in the artifact. The optional input `history-branch: crypt-history` also keeps it on that branch through `scripts/ci/history-branch.sh`. A pure module, `src/report/limb-history.ts`, parses, appends and aggregates the lines. The autopsy page and a new War Room panel show open KEV limbs over time, age per limb, deadline breaches and mean time to heal. The War Room reads a seed of the real crypt-demo events of 2026-11-18. `typecheck`, `build:web` and the full suite (1169 tests) pass.

Watch for: (1) the seed reports a mean time to heal of 0.05 hours (3 minutes) for lodash, but the HEALED line has no recorded time. The number is PR-open to merge, shown under a "heal" label (confirmed). (2) The seed holds no KEV limb, so the "open KEV over time" series is 0, 0 (confirmed). (3) `gazette` and `autopsy` each call `now()` separately, so one run can add two run points (likely). (4) The push/pull path of `history-branch.sh` has no test (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The history is a plain append-only JSONL file with a strict parser. Junk lines are skipped, unknown values stay `null`, and only CODEOWNERS teams are accepted as owners. Aggregation is a pure function that sorts and de-duplicates lines, so the report and the War Room share one code path (the War Room gets it through the `build:web` output).

Persistence is guarded in two places, the Action (`action.sh` calls `check`) and the script itself. Only the literal branch `crypt-history` is accepted, and it must differ from the default branch. The push refspec is fixed to `refs/heads/crypt-history`, and every failure after the guard exits 0 with a warning, so history loss is silent but never breaks a run.

The real seed is where the change falls short of "unknown stays unknown" and "nothing invented". The three lines are real events, but the aggregate turns them into a heal duration that the history does not hold. The demo also cannot show a KEV trend, because the seed has no KEV limb.

## Heal time computed from the merge, not the heal

`aggregate` sets `fixedAt` to the earliest Landed or Healed line that has a ts. For the seed that is the merge at 18:26:40Z, because the Healed line has `ts: null`. A limb whose last state is Healed then gets `hours = (fixedAt - first)`, and it enters `healHours`. The output is a mean time to heal of 3 minutes with `healTimesKnown = 1` (confirmed by `tests/limb-history.test.ts`, "shows the lodash heal", which asserts `0.05`).

Two real timestamps are subtracted and the result is presented under the label of an event that has no timestamp. The War Room note ("Heal time is the landing time of the fix") and the footnote disclose this, but the headline figure is the large `big` element, and a CISO or VC reader will take it as time to heal. The user instruction says unknown stays unknown, and PROOF.md itself records the reraise as having no time. The honest result for the seed is `unknown` for mean time to heal. Time to land (3 minutes) can be shown as its own labelled figure.

The same assumption sits in the first line. PROOF.md gives 18:23:40Z as the time PR #1 was opened. The seed uses it as the Rotting line, so "age" starts at fix-PR-open and not at detection. Step 1 of PROOF.md ("Found") has no time. The lodash `kev: false` is a reasonable reading of "Rotting" but is not stated in PROOF.md (possible; check against the run summaries linked there).

## Seed gives no open-KEV trend

The seed has two dated runs, both with `openKev = 0`, and one undated line that appears in no run point. The panel therefore renders a flat zero line next to a real heal. The jquery KEV limb is the story the roadmap's CISO persona cares about, but PROOF.md has no timed event for it, so leaving it out is correct under "nothing invented". The gap is that the done-when ("two runs on crypt-demo produce a trend with the real heal of lodash") is met only in the weakest sense. The sample history on the autopsy page does show a KEV series, labelled `sample`.

## Run identity when autopsy and gazette both record

In `scripts/cli/autopsy.ts` and `gazette.ts`, `recordLimbHistory(io, path, creature, now())` is called with a fresh clock reading. `appendLines` replaces a line only when ts and limb are equal, so two commands in one CI job, or two invocations seconds apart, each add a full set of lines and produce two points in `runs`. The deadline logic reads the earliest prior deadline, so breaches stay correct, but the trend gets noise and the file grows by one line per limb per invocation. The user manual says "A rerun with the same time adds nothing twice", which is true only in tests.

## Branch persistence guard

Two behaviours of the guard are worth knowing. First, `DEFAULT_BRANCH` comes from `github.event.repository.default_branch`. An empty value makes `check` fail and the run exit with a usage error, which is fail-closed but kills the whole report instead of skipping history. Second, if the history branch moved between pull and push (two concurrent runs), the push is rejected as non-fast-forward and the run's lines are dropped with only a warning. Both are consistent with the "history is a convenience" stance, but neither is tested.

Pulled content comes from a branch any contents-writer can change. It is parsed with the same strict parser (limb pattern, team pattern, ISO times), so a tampered file can skew numbers but cannot inject markup, because the autopsy page escapes every value and the War Room uses `textContent`.

## Tests

The property tests cover the aggregation counts as asked (state counts sum to run lines, run lines plus undated equal the line count, bounds on breaches and limbs). Not tested: `history-branch.sh` `pull` and `push` against a real repo, `action.sh` wiring, and `drawHistory` in `war-room.js` beyond string checks on its source.
